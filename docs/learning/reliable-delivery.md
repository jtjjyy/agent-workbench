# 可靠任务、代码交付与 Windows 桌面数据

本轮由开发 Agent 编写，用户确认范围并参与需求选择。Pi 1.1.0 是唯一模型及工具循环内核；任务持久化、变更审批、交付证据和桌面维护是本项目应用层实现。未运行测试、类型检查、Lint、构建、打包、启动或真实模型请求，以下验收均为待执行项，不能写成通过。

## 使用流程

1. 选择并授权工作区，配置模型；桌面与数据面板可确认首次配置。保存配置不发起模型连接测试。
2. 发送任务；模型可通过 `update_task_plan` 保存真实步骤，任务面板显示计划、状态及断点摘要。只有绑定成功工具记录的步骤才允许声明完成，工具记录并不能独立证明语义正确。
3. 暂停或取消会停止当前运行并保存记录，不撤销已经执行的操作。关闭程序与重启恢复会将未结束的记录保留为中断。
4. 续接前重新选择并授权原目录。未知副作用需要核对真实文件、命令或页面状态；勾选确认只允许继续，不能将未知结果改成确定成功。续接创建新运行编号，发送原任务及有限摘要，不重新提交旧工具调用或审批。
5. 代码任务通过 `propose_change_set` 申请最多二十项文件变更。核对完整差异与路径后批准整批；工具核对原内容哈希及目录身份，再逐项应用。变更期间外部编辑会使旧提案失效。部分失败保存实际状态，需人工处理，不能声称整批原子性。
6. 交付状态按钮和 `deliver_changes` 读取当前文件哈希及已保存的验证证据。当前验证策略关闭，应用变更后仍为未验证，不能把模型最后回复当作代码交付完成。
7. 空闲时选择备份类别，保存本地备份。恢复选定类别会替换对应本地数据，先保留恢复前备份，操作后必须关闭程序再启动。备份不包含工作区源码、浏览器状态或项目索引；密钥为系统密文，不能保证跨电脑、跨账号解密。

## 真实边界

任务和变更存储先写临时文件、同步并替换；事件日志串行追加，没有断电级事务保证。这些存储之间不存在跨文件事务，恢复时保留不确定状态，不能猜测副作用是否执行。目录身份与哈希复查减少误覆盖，不能抵御同权限恶意进程的所有路径竞态。

交付快照覆盖变更集中涉及的路径，不是全仓库内容快照。验证命令可能读取或修改其他路径，其退出码为零也不证明代码语义正确、隐藏测试通过或安全性完整。命令执行使用当前用户权限，工作目录与审批都不是操作系统沙箱。

当前每轮最多 24 次模型请求、48 次工具尝试，仍受配置超时和字符上限约束。增大上限没有成本或质量实测证据，不等于任务可以无限持续；达到限制后保存状态，由用户核对后续接。没有定时后台无限续跑、自动 Git 提交或推送。

目前遇到部分/未知变更记录会阻止本任务再次提出批次。人工核对后可在新任务中基于当前文件重新提案，不能删除旧证据假装成功。恢复失败时有安全副本及标记，部分恢复需要人工处理；不承诺所有故障都可自动回滚。

## 验收分层与个人练习

Mock 层先覆盖状态、预算、存储故障、哈希冲突与审批；真实模型层再记录模型 ID、配置、用量和失败原因；端到端层最后检查 Windows 程序、安装、迁移、恢复和关闭流程。开发任务集与保留测试集分开，不拿同一批调参任务冒充独立评测。

个人练习：画出一个工具从模型提案到本地记录、审批、执行与结果落盘的顺序；人工修改一个已审批文件，解释冲突来源；用临时数据目录模拟恢复失败，解释安全副本与重启门槛。所有执行练习等用户恢复验证后进行。
