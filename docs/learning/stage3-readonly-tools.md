## 实际接口与授权边界

`WorkspaceSession` 保持以下固定接口，不修改共享状态结构：

```ts
async select(root: string): Promise<WorkspaceState>
read(): WorkspaceState
setConsent(consent: boolean): WorkspaceState
clear(): WorkspaceState
snapshot(): WorkspaceState
```

`select` 的路径只能由主进程原生 dialog 得到；本模块没有创建接受任意 path 的 IPC。调用前即清空旧选择与同意，因此失败也不会继续保留旧授权。选择成功保存 canonical 普通目录，`dataEgressConsent` 总是 false。状态和根指纹只留在进程内存，不读写配置或密码。并发选择通过版本号拒绝过时结果。

父 Agent 必须在 `select` 的失败分支同步界面：捕获安全错误后读取 `session.read()`，不能只显示错误而继续展示原目录或原同意状态。若失败来自被后续选择替代的旧请求，则以 `read()` 返回的当前状态为准，不用旧请求结果覆盖新选择。

模块内 `selectedRoots` 在选择时保存 canonical root 对应的 `bigint dev/ino`，避免大 inode 转成浮点数丢失精度，不是在每次 execute 时重新给当前同名目录授权。工具开始、路径检查和返回前会对照选择时的指纹；同名普通目录换成不同 `dev/ino` 会被拒绝。清空或重新选择释放该会话的旧登记，保留对其他会话登记的对象身份判断。应用应使用父 Agent 持有的单个活动 `WorkspaceSession`，不依赖多个同路径会话互相独立授权。

`createReadonlyTools(workspace): AgentTool[]` 依赖已安装的 `@earendil-works/pi-agent-core@1.1.0` 和 `typebox@1.3.27`。无目录或没有外发同意时返回空数组；伪造或从磁盘恢复的 `WorkspaceState` 不会创建合法的内存指纹登记，执行时被拒绝。工具集合捕获工作区状态快照，不是持续订阅授权变化：父 Agent 必须继续保证运行中工作区变更互斥、撤销后不继续请求、每个新任务从当前状态创建工具，不复用旧快照或自动重放工具。

| 工具 | 参数与真实语义 |
| --- | --- |
| `list_files` | `{ path?: string }`，默认 `.`；只遍历目录，使用路径、普通文件类型、扩展名和大小等元数据筛选，不打开文件正文，不是完整目录树。纯列表没有引用文本行，`sources` 为空。 |
| `read_file` | `{ path: string, startLine?: number, endLine?: number }`；行号从 1 开始，默认从第 1 行展示，最多 120 行。明确的结束行小于上限时只返回请求范围，不把未请求部分称为丢失。 |
| `search_text` | `{ query: string, path?: string }`，默认 `.`，也可指定单文件；单行、非空、区分大小写的字面搜索，以 `indexOf` 匹配，不使用搜索正则、shell 或外部命令。同一行多次出现只计一个匹配。 |

三个 schema 均设置 `additionalProperties: false`；执行器还独立拒绝未定义字段、错误类型和非安全整数，不执行类型强制转换。路径只允许工作区相对路径，目录工具可使用单独的 `.`；拒绝内嵌 `.`、`..`、空片段、绝对路径、冒号、ADS、设备名、控制字符和不安全名称。输入中的普通反斜杠分隔会规范成输出的 slash；来源本身绝不含反斜杠。

## 实际资源上限

| 上限 | 当前实现的计数方式 |
| --- | --- |
| 1000 个目录项 | 每次工具执行全遍历共享预算；排除项和目录项也计数。使用 `opendir`、`bufferSize: 1` 和逐项 `directory.read`，不使用无上限 `readdir`，不先读取整树。 |
| 100 个候选文本文件 | 全遍历共享预算；白名单扩展名的普通文件一旦遇到就计数，即使后来因过大、二进制或变化而拒绝。列表仅检查元数据；搜索按候选逐文件读取。直接读取或单文件搜索只访问请求的一个文件。 |
| 深度 8 | 以相对工作区的路径片段数计数，文件名也算一层；根目录深度为 0。第八层目录不再展开；指定子目录不能重置深度预算。 |
| 单文件 256 KiB | 精确为 262144 字节；只分配已检查且不超限的文件大小缓冲区。`handle.read` 每块最多 16 KiB，总读取不超过该文件大小，读取前后核对句柄与路径的身份、大小、mtime、ctime。增长、缩短或变化会拒绝结果，不为大文件返回伪造的部分 hash。 |
| 单工具 4000 UTF-16 单元 | 按整个返回对象 `JSON.stringify(result).length` 计数，包含 `content`、`details`、`isError` 和 JSON 转义，因此比只限制模型正文更严格。保留 600 单元摘要预算，摘要在正文和 details 中各一份；实际内容可能提前停止。不是 token 限额。 |
| `read_file` 最多 120 行 | 每行最多展示 1000 UTF-16 单元，整工具预算可能更早限制行数。长行、120 行和总输出预算分别给出截断说明；不为了凑满行数破坏证据字段。 |
| `search_text` 最多 12 匹配 | 计匹配行，不计某行内重复次数。达到上限即停并说明未继续检查，不能推断不存在第 13 个匹配；总输出预算通常可能先触发。 |
| 来源最多 12，摘录最多 240 | 来源路径最长 512 UTF-16 单元，slash 分隔，无冒号、反斜杠、空片段、`.` 或 `..`。超长或控制字符名称在遍历时跳过，直接请求返回安全错误。摘录截断不拆开末尾代理对。 |
| 搜索文本最多 200 | UTF-16 单元，拒绝空白查询及换行/控制字符，只作单行字面搜索。 |

目录遍历按文件系统提供的顺序深度优先执行，不承诺排序、总文件数或完整性。排除、不支持和读取失败的项只给汇总数量，不显示被拒绝名称或原始错误。达到扫描限额时，即使剩余目录可能刚好为空，也保守说明未继续检查，不额外枚举来证明完整性。

100 个候选文件都接近上限时，一次目录搜索仍可能读取约 25 MiB；没有全目录总字节限额或缓存索引。`list_files` 不读取任何文件正文，只有目录项与文件系统元数据访问。搜索和读取不会保存整棵树的文件内容，但会同时持有当前文件的字节与解码文本，以及有界结果和递归目录句柄。上限不等于固定的延迟或内存峰值承诺。

## 文件策略与来源含义

默认只允许 `TEXT_EXTENSIONS` 中列明的代码或文档扩展名；典型允许项包括 `.ts/.tsx/.js/.json/.md/.txt/.yaml/.toml/.py/.rs/.go/.c/.cpp/.h/.ino/.html/.css/.vue/.svelte/.sql/.tex`。完整列表以该常量为准。没有扩展名的 Makefile、Dockerfile，未知扩展名、图片、压缩包等不开放；不因文件内容看起来像文本自动放宽。

敏感及排除策略覆盖 `.env*`、常见密码/凭据/密钥/证书名称和扩展名，以及 `.git`、`node_modules`、`dist`、`build`、`logs`、缓存、虚拟环境、凭据目录等。匹配不区分大小写，对相对路径各片段应用，也拒绝选中根目录或父链名称落入排除范围的工具访问。名称规则可能误拒绝普通文档，不是完美的凭据识别器。只接受有效 UTF-8，拒绝 NUL 和不允许的 C0 控制字符、DEL；UTF-16 或无法合法解码的编码不会被自动转码。

上述正文检查发生在 `read_file` 和 `search_text`。仅检查元数据的列表无法识别伪装成 `.ts` 等扩展名的二进制正文，因此只把文件称为候选；后续读取或搜索仍会做内容检查并拒绝检测到的非文本，不为了列名称先读取整个候选集合。

每个工具成功或错误都固定返回 `details: { summary, sources }`。普通工具失败使用 `isError: true`、中文安全摘要和空来源；取消不包装成结果，而是抛出 signal 的原 reason。原始文件系统异常不会被拼入摘要。最终输出再次核对来源字段，遵循现有 `shared/contracts.ts` 的 `validSource` 约束，不更改共享协议。

来源的 SHA-256 为整份已读取有界文件的原始字节哈希，64 位小写十六进制；不是所展示几行或摘录的 hash。模型 `content` 中显式包含证据的相对路径、行范围、hash 和摘录，而不只把这些放进界面 details。

读取结果通常只有一个来源，摘录取请求范围起始部分，至多 240 UTF-16 单元，`startLine/endLine` 只覆盖实际摘录出现的行；正文可以展示更长的请求范围，并另外报告正文行范围。LF、CRLF、单独 CR 都作为换行；文件末尾的换行终止符不额外制造一个不存在的行。空文件或起始行越界不伪造来源。搜索来源每项对应真实匹配行，摘录可能只是该行的局部窗口。

展示前隐藏文本中常见原始形式的工作区绝对根路径，片段里可能出现 `[工作区路径已隐藏]`；此时摘要说明脱敏，hash 仍对应未修改原始字节。若查询命中被隐藏的路径，显示摘录可能不含查询原文，并单独说明。摘录是有限展示快照，不是完整文件的无损保存；本地 journal 仍可能保存用户代码片段，需同样保护。

## 不能承诺的边界

- 这是应用层路径、文件及输出策略，不是操作系统文件系统沙箱；不能抵御同权限恶意进程。
- `lstat/realpath`、根目录指纹、打开后身份检查及读取前后元数据比较能拒绝检测到的变化，不能原子化检查与打开，也不能杜绝路径竞态、inode 重用、硬链接或可伪装的时间戳问题。指纹依赖运行时文件系统暴露的 `dev/ino`，不同平台行为仍待验证。
- 支持的平台额外使用 `O_NOFOLLOW/O_NONBLOCK`；Windows 不依赖这些打开标志，而依赖链检查与身份检查，不能声称等价于内核级目录句柄隔离。
- `signal` 在遍历、读取、处理文本与输出前后检查，取消后不返回成功结果，但不能保证已开始的每个原生文件系统调用会立即被中断。
- 文件名排除不能保证普通源码没有密码、令牌或证书文本；本轮没有读取任何密码来评估规则，也没有做内容级凭据检测。常见根路径脱敏不是通用秘密脱敏器。
- 仓库文本与工具输出可能包含提示注入，仍是不可信数据，不能提升工具权限。来源 hash 不验证模型推理、事实结论或每个模型引用，也不证明读取后的现文件未变化。
- 限额都是每次工具执行的上限；总任务请求数、工具尝试数、累计上下文和取消后的模型请求约束由父 Agent 负责，不能由此推断全任务已经有完整验收证据。

## 恢复验证后的证据清单

所有项目目前均待执行，记录样例应只使用临时构造的测试文件，不使用真实秘密或聊天中暴露的密钥。

1. 使用固定样例目录验证三工具正常返回、空结果、参数拒绝和每种限额；明确“符合格式”与“已运行验收”是不同结论。
2. 覆盖 512/513 单元路径、控制字符、Windows ADS/设备名、父链和目标链接、相似目录前缀越界、普通根目录替换、同一文件读取期间变化。
3. 覆盖源文件 LF/CRLF/CR、空文件、UTF-8 BOM、长行、代理对、起始行越界；用独立 hash 证据比较整文件原始字节，核对摘录行号与脱敏说明。
4. 验证三工具返回的 `details.sources` 能通过现有 journal 的来源规则；不放宽共享校验，不把失败的写入误当作运行成功。
5. 覆盖遍历和分块读取中取消、资源释放、任务中授权变化被父 Agent 阻止，以及取消或撤销后无下一次外发请求。
6. 把确定性工具测试、桌面接线 E2E 和另行授权的真实模型调用分开；没有任何一类的结果可以替代其余类别的证据。
