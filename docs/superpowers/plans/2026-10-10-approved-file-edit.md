# 第四阶段：限定文件修改、审批与差异预览

> 实施方式：主 Agent 接线，两个并行子 Agent 分别负责执行器和界面；源码审阅不等于运行验收。

## 目标与边界

用户已要求继续上一阶段提出的限定修改、审批和 Diff。采用已有文件唯一片段替换方案：比整文件覆盖更容易保留其他已有改动，比引入任意 shell 或通用补丁执行更小。模型不能直接提交审批、选择绝对路径或改变已经展示的提案。此阶段不做新建、删除、重命名、命令执行或自动回滚。

技术沿用 Electron、React、TypeScript 和唯一的 Pi 内核；差异展示复用 jsdiff。主进程验证文件并创建提案；提案文本只在本次任务内存和审批界面存在；持久化日志记录 ID、相对路径、前后哈希和结果，不保存完整差异正文。普通聊天历史不能重用仓库任务证据。

## 全局约束

- 所有新增界面、错误、文档与回复使用简体中文，必要代码原文保留。
- 不运行测试、类型检查、lint、build、打包、浏览器验证或真实模型调用；不自动启动或重启客户端。
- 不使用聊天中暴露密钥，不回退已有代码，不自动提交或推送。
- 每次审批绑定任务、应用生成工具调用 ID、单次审批 ID、工作区、路径和前后 SHA-256；审批一次消费，60 秒到期，任务超时仍包含审批时间。
- 只允许白名单 UTF-8 普通文件，32 KiB、前后各 12000 UTF-16 单元；相对路径、敏感路径排除、工作区身份检查沿用只读策略，额外拒绝硬链接。
- 执行前核对原字节哈希与文件身份，冲突拒绝写入。不把策略或确认弹窗称为 OS 沙箱，不保证跨进程原子比较并替换。
- 先持久化审批决定及写入开始，再调用执行器；写入之后取消不能视为回滚；中断不重放，缺完成事件时结果未知。

## 实施任务

- [x] 协议：`src/shared/file-edit.ts` 定义提案、审批身份、决定与执行结果；扩展 contracts、日志验证及中文事件名称。仅源码接入，未验证。
- [x] 执行器：`src/main/tools/file-edit-tool.ts` 暴露 `createFileEditTool(workspace, onEdit)`，工具名 `replace_text`，参数严格限定 `path/oldText/newText`；只替换唯一非空片段，复用已有路径检查，审批后重新核对，限制副作用。仅源码接入，未验证。
- [x] 运行时：Pi 注册工具，协调器管理一次性审批；IPC 只能读当前提案及提交 ID/摘要/决定，不接受新路径或改后正文。仅源码接入，未验证。
- [x] 界面：中文审批面板，完整有界 Diff、前后哈希、到期、拒绝与批准，修改状态轨迹；文件内容不按 HTML 执行。仅源码接入，未验证。
- [x] 文档：更新能力边界、依赖许可和知识映射，输出第四阶段说明。仅源码接入，未验证。

实现结论：本阶段代码与测试源码已写入；测试、类型检查、lint、build、打包、桌面端到端和真实模型调用均待用户明确恢复后执行。

## 待执行测试与验收

所有以下任务仅设计或编写，未执行：唯一匹配与零/多匹配、已有改动保留、UTF-8/大小限制、穿越/链接/硬链接/敏感路径、文件在审批中变化、伪造和重复审批、过期与取消、日志在开始前/后失败、写入部分失败、任务中断后不重放、原样显示代码与特殊字符。Mock 与真实模型、桌面端到端分别记录，当前无通过率或性能结论。

验收场景：选可外发的实验仓库，请求替换一处明确内容，查看实际工具调用和 Diff；拒绝时原文件不变；批准时只写确认的提案；等待期间编辑文件应冲突；取消或重启不能沿用旧审批。尚未运行这些场景。

## 风险

Windows 常规 Node 文件 API 不提供跨进程的原子 compare-and-swap；路径和文件状态复查不能消除同权限恶意进程、检查写入间竞态、所有断电与部分写入情形。发生不确定结果时停下人工查看文件，不重试、不自动覆盖用户改动。未经验收不得把新增写入能力称为可靠生产级执行。
