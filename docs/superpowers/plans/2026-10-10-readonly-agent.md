# 第三阶段：授权工作区与只读 Agent 实现计划

执行方式：使用 subagent-driven-development，权限工具和客户端界面并行，主 Agent 负责协议、Pi 内核和运行协调。沿用已经批准的全项目设计，不重新改变技术栈。

## 目标与边界

目标：选择一个本地工作区，单独同意仓库内容外发后，DeepSeek 经 Pi 内核调用文件列表、文件读取、字面文本搜索，并展示实际工具轨迹及来源快照。

非目标：写文件、执行命令、浏览器、MCP、多 Agent 产品功能、语义检索、增量索引、自动恢复工具调用。Mock 保持无工具、无网络，不伪造工具使用。

选择：复用 Pi 内核（推荐且沿用批准设计）；自行实现循环会重复维护；直接使用完整编码 CLI 会扩大本阶段权限与集成范围，因此不采用后两者。

## 已核对的接口事实

2026-10-10 查询 npm 并读取安装后的 1.1.0 发行源码：`@earendil-works/pi-agent-core@1.1.0` 依赖 `pi-ai ^1.1.0`、`typebox 1.3.27`，MIT，Node >=22.19.0。现有 pi-ai 固定 1.1.0。

`Agent` 构造需要 `streamFn`，提供 `prepareRequest`、`beforeToolCall`、顺序工具执行；`subscribe` 的 Promise 会被等待。`prompt` 会把运行失败转换为内部失败消息，所以应用须独立捕获持久化错误及最终状态，不能把 Promise resolve 当成功。

参考包的 StreamFn 要返回事件流而非抛异常；请求预算在 `prepareRequest` 检查。工具调用参数既经 Pi schema 验证，也经应用执行器验证。以发行包源码和 package-lock integrity 为依据，不把移动 main 分支当固定版本。

## 架构与接口

`src/shared/workspace.ts`：工作区状态、命令结果、来源证据、工具进度。
`src/main/workspace/workspace-session.ts`：主进程原生目录选择结果授权，只在本次启动有效；重启默认无目录、无外发同意。
`src/main/tools/readonly-tools.ts`：三种 schema 工具，路径和输出边界，纯只读。
`src/main/agent/deepseek-provider.ts`：配置及 Mock 路由；`pi-agent-runtime.ts` 保留唯一 Pi 单 Agent 工具循环，`deepseek-transport.ts` 负责受限传输及服务端用量读取。
`src/main/agent/run-coordinator.ts`：工作区变更与任务互斥，先持久化工具事件再执行/广播，中断不重放。
`src/shared/contracts.ts`、preload、IPC、reducer：新增可重放工具事件，仍接受旧 schema-v1 日志。
`src/renderer/components/WorkspaceBar.tsx`、`ToolTrace.tsx`：中文授权栏和运行证据，保持既有工作台设计。

## 测试与验收（本轮不执行）

遵守用户暂停测试验证要求：不运行单测、lint、typecheck、打包、E2E、界面自动化或真实模型调用；不把检查源码/安装依赖算测试通过。以下均为恢复验证后的待验收项。

Mock：仍不调用工具；正常列举/读取/字面搜索；未知工具/非法参数；12 次工具与8次请求预算；缺失用量显示未知；无授权时请求无工具定义。
安全：路径穿越、绝对路径、Windows ADS/设备名、符号链接/junction、根目录替换、敏感文件、二进制、超大文件、取消、持久化失败。
真实模型（需单独启用且使用重新生成的密钥）：读取选中仓库并说明架构，检索无结果，限流和超时，取消后无下一次模型请求。
E2E：目录选择与撤销授权、任务中禁用变更、日志重放工具状态、重启授权清空、旧日志加载、证据快照展示。

## 风险

应用路径策略与 Electron 隔离不是 OS 文件系统沙箱。检查和打开之间仍有路径竞态，不能抵御同权限恶意进程。敏感文件名阻止不能保证普通源码没有凭据，授权时明确范围；仓库文件和工具输出可能含提示注入，不提升其权限。

工具结果存入有限的模型上下文，日志只保存受限摘要和来源片段；这仍可能含用户代码，本地日志同样需保护。来源 hash 是读取时快照，不能保证现文件未变化。新任务不自动外发旧仓库问答历史，避免撤销授权后历史泄露。
