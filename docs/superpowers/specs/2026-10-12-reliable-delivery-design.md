# 可靠任务与桌面交付设计

用户于 2026-10-12 确认增量扩展现有模块化单体方案。本次只实现已确认的三个缺口，不重写 Pi 内核。

## 范围与约束

- Electron、React、TypeScript、Pi；单用户、同一时刻一个活动任务。
- 中文界面与文档。保留历史消息和用户已有代码改动。
- 用户暂停测试验证：不执行测试、类型检查、构建、打包或真实模型请求。实现可以包含测试源码和待执行验收说明，不能宣称通过。
- 不使用聊天中暴露的密钥，不提交密钥或真实模型日志。
- 不承诺原子多文件事务、通用回滚、命令沙箱或自动恢复有副作用的调用。

## 一、任务持久化与续接

新增独立版本化任务存储，保存任务输入、工作区身份、运行编号、计划、工具状态、审批状态、检查点和有限上下文。采用串行写入、临时文件与重命名，失败时阻止继续执行。事件日志继续作为运行追踪，不维护第二套 Agent 内核。

支持暂停、取消和用户触发的续接；进程重启将活动任务转为中断。续接是新一轮 Pi 调用，传入持久化摘要和计划，不重复发送旧工具调用。重新选择相同工作区并授权才能续接。已完成步骤仅作为历史事实，文件内容必须重新读取。存在未确认命令、浏览器交互或部分文件应用时，用户核对后才能继续；不把确认当作证明命令未执行。

## 二、变更、验证、修复、交付

新增结构化变更集工具，支持创建、修改、删除、重命名 UTF-8 文本文件，先形成所有差异并审批，绑定任务、工作区、所有文件前后哈希和具体操作。路径限制沿用已有文件工具边界。应用前逐项重新核对，逐文件记录结果，部分失败保留结果，不覆盖用户变更也不自动回滚。

新增验证工具，复用具体命令审批、超时和取消，保存真实退出码、命令输出摘要、尝试次数与对应变更版本。用户暂停验证时，运行时禁止验证工具且提示未验证。恢复验证后支持最多三次失败修复，修复后旧验证证据失效。交付工具核对变更现状，输出变更清单、验证状态和风险；当前仅生成本地交付报告，不自动提交或推送 Git。

## 三、桌面稳定交付

统一开发与打包数据目录；保留旧数据并明确版本迁移策略。增加持久化首次配置状态、版本与路径信息、诊断导出、包含配置密文的本地备份与受控恢复。记录启动失败阶段，不打印任意错误对象或密钥。单实例重复启动聚焦已有窗口，修复关闭流程的资源归属。

提供明确的开发、便携版、安装版入口。打包仅允许使用当前源码产物并提供准备脚本与发布说明；由于用户暂停验证，本轮不生成也不声称验证新的安装包。

## 待恢复验证后的验收

1. 创建任务、更新计划、暂停、重启，重新授权相同工作区后继续；已完成工具不自动重放。
2. 命令执行中断后，续接前展示未知状态并要求核对；审批不能复用。
3. 多文件修改、新建、删除、重命名展示完整 Diff；用户修改目标文件后拒绝应用。
4. 部分应用失败保留每个文件状态；不声称全成功。
5. 验证失败、修复、再次验证、交付，报告区分未运行与成功；本轮禁止实际验证。
6. 首次配置、重复启动、配置损坏、迁移、日志导出和本地备份恢复。
7. Windows 安装版与便携版均显示当前版本和相同数据目录。
