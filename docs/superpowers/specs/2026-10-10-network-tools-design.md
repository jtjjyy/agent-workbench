# 联网工具解耦设计

## 目标

让 Agent 在未选择代码工作区时也能使用网页搜索和网页读取，同时保持数据外发授权、模型配置和网络安全限制。代码读取、文件修改、命令执行和浏览器交互继续遵循各自的工作区与审批边界。

## 现状与根因

`web_search` 和 `web_fetch` 已经实现，但 `runPiAgent` 使用同一个 `authorized` 条件注册所有工具。该条件同时要求工作区存在且允许数据外发，因此没有工作区时联网工具不会注册，模型只能声明没有联网能力。

## 设计

### 授权分层

- `workspaceAuthorized`：存在已选择工作区，且用户允许工作区数据外发。它控制代码检索、知识库、文件修改和 PowerShell。
- `networkAuthorized`：用户允许数据外发。它控制网页搜索和网页读取，不要求工作区。
- 浏览器工具继续要求 `workspaceAuthorized`，且点击、输入仍逐次审批。浏览器会话属于受控桌面交互，不把它等同于网络读取。

### 数据流

1. 用户在模型设置中启用 DeepSeek，并明确同意数据外发。
2. 运行时读取当前设置和工作区快照。
3. DeepSeek Agent 始终根据 `networkAuthorized` 注册 `web_search`、`web_fetch`。
4. 只有 `workspaceAuthorized` 时才注册代码、知识、文件、命令和浏览器工具。
5. 网页内容只作为本次工具结果进入上下文，不自动写入记忆或项目索引。

### 安全边界

- 只允许 HTTP/HTTPS。
- 拒绝 localhost、环回、私网、链路本地和 `.local` 地址。
- 禁止自动跟随不受检查的跳转；仅允许有限次跳转并逐次检查目标地址。
- 每次请求有超时、响应正文长度上限和取消信号。
- 搜索结果只是候选来源，提示模型继续读取并核对原页面。
- 网络工具不是浏览器沙箱，也不阻止操作系统或第三方服务看到请求元数据。

## 取舍

推荐将“网络授权”直接复用现有数据外发同意字段，避免新增一套设置状态；工作区权限仍单独由工作区选择和授权控制。这样改动小、用户能理解，也不会把选择工作区误认为网络权限。

## 验收标准

- DeepSeek + 数据外发同意 + 未选择工作区时，Agent 工具列表包含 `web_search` 和 `web_fetch`。
- 同一状态下不包含代码读写、命令执行、浏览器交互工具。
- 未同意数据外发时，联网工具不注册。
- 已选择并授权工作区时，原有工作区工具继续注册，联网工具也同时注册。
- 工具轨迹仍显示中文名称和耗时；网络结果包含来源 URL 和抓取时间。

## 非目标

- 本次不引入付费搜索 API。
- 本次不实现网页正文的持久化索引、记忆写入或引用数据库。
- 本次不把浏览器窗口改造成通用无沙箱浏览器。
