# 第九阶段：Skills 设计

## 目标

为 Agent Workbench 增加本地、可管理、声明式的 Skills。Skill 只提供任务方法、提示词片段和匹配关键词，不拥有任意代码执行能力，也不能扩大工作区、文件写入、命令或 MCP 权限。

## 方案

Skill 由结构化元数据和 Markdown 指令组成。首版内置三个 Skill：代码仓库理解、技术资料调研、变更验证与复盘。运行任务时，主进程根据用户输入匹配已启用 Skill，将有限长度的 Skill 指令拼接进 Agent 系统提示；未匹配的 Skill 不进入上下文。用户可在中文面板中启用、禁用和查看 Skill。

用户 Skill 只接受本地 `SKILL.md` 文本和受限元数据；不加载 Skill 中的 JavaScript、命令或动态工具定义。工作区权限、文件修改审批和知识检索权限仍由既有运行时决定。

## 数据流

1. `SkillService` 从内置目录和用户数据目录读取 Skill 定义。
2. 对名称、描述、关键词、指令长度和工具声明进行校验。
3. `RunCoordinator` 在任务开始前读取启用状态并按输入匹配 Skill。
4. `DeepSeekProvider` 将匹配结果传递给 Pi 运行时。
5. Pi 运行时把 Skill 指令作为受限系统提示片段，不改变工具集合。
6. Renderer 通过 IPC 展示和切换启用状态。

## 安全与边界

- Skill 内容是本地配置，不是安全策略；模型仍必须服从运行时权限。
- Skill 不得声明未注册工具，不得要求绕过审批，不得读取密钥或执行任意命令。
- 用户 Skill 和索引、记忆一样属于本地明文配置。
- 不把 Skill 内容自动发送给模型之外的服务；匹配到的 Skill 会随任务系统提示发送给当前模型。
